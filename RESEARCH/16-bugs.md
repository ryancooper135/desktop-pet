# Охота на баги (волна 30)

Только настоящие баги: симптом → причина → починка → тест. Фич, баланса, вида и текстов волна не меняет.
Решения — DECISIONS.md, «Волна 30: охота на баги». Регрессии — `app/Tests/BugHuntTests.swift` (Linux, WSL).

## 1. «Щенок против зомби» платил мёртвому псу

- **Симптом.** Пёс умер, пока шёл раунд «Зомби» (голод догнал время в `catchUp` при выходе из игры), — итог
  раунда всё равно давал монеты. Монеты уходили в кошелёк, который по правилу волны 13 переходит новому щенку,
  и съедали дневной потолок мини-игр.
- **Причина.** `ZombieRun.finish` считал `got = min(wish, coinsLeft)` без проверки `f.pet.alive`. «Лови мячик»
  и «Блок Дуо» эту проверку имеют с волны 13 (DECISIONS, «Мини-игры после смерти»), зомби (тоже волна 13,
  но позже) её не получили.
- **Починка.** `got = f.pet.alive ? min(wish, coinsLeft) : 0`, `capped = f.pet.alive && got < wish` — как у
  `CatchGame.finish`. Рекорд и счётчик партий остаются, `play` ядро и так отклоняет (`dead`).
- **Тест.** `BugHuntTests.testZombieFinishAfterDeathPaysNothing` (до починки — 5 провалов: монеты, итог,
  «потолок», текст награды, кошелёк), контроль `testZombieFinishAliveStillPays`.

## 2. Ссылка pet://shop / pet://kitchen оставляла «висящий» флаг листа

- **Симптом.** pet://shop открывает автомат, а лавку — через 0,8 с поверх него. Если за эти 0,8 с автомат
  закрыли (свайп вниз, pet://home, другая ссылка из виджета/Spotlight), `showShop` всё равно становился `true`
  без автомата. Лист лавки висит внутри автомата, поэтому его не видно, но `anyCover` (есть открытый лист)
  оставался `true`: не показывались подсказки-гайды и не снималась открытка-кадр, а при следующем открытии
  автомата лавка выскакивала сама. С кухней поверх «Дома» — то же. Так же отложенный шаг `closeFirst`
  (закрыть всё → через 0,8 с открыть цель) не отменялся новой ссылкой: две ссылки подряд открывали обе цели
  по очереди, вторая поверх первой — тот самый «мёртвый флаг» волны 25.
- **Причина.** `AppModel.route` / `open` запускали `Task { sleep; флаг = true }` без отмены и без проверки, что
  родительский лист ещё открыт.
- **Починка.** Один `routeTask` в AppModel: новая ссылка и `closeAllSheets` его отменяют. Второй шаг лавки/кухни
  ставит флаг, только если `DeepLink.mayFollow(host, open: openRoutes)` — открыт ровно родитель (автомат или
  «Дом»), ни ребёнка, ни чужих листов. Логика — в Shared (`DeepLink.followUp`, `DeepLink.mayFollow`).
- **Тест.** `BugHuntTests.testDeepLinkFollowUpOnlyForNestedSheets`, `testDeepLinkFollowUpNeedsParentStillOpen`.
  Сам `AppModel` на Linux не собирается, поэтому тестируется решение «можно ли второй шаг», а отмену задачи
  проверяют UI-тесты ссылок (ui-68 лавка, кухня, PET_THEN).

## 3. Мигающий UI-тест `testStates68Shop` (лавка дня)

- **Симптом.** Прогон main 39449839223, попытка 1, шард «test 2»: «ui-68: после покупки нет «Куплено»».
  Перезапуск зелёный.
- **Разбор xcresult.** Лавка открылась (`shop.screen` за 3,5 с), снимок `ui-68-shop` сделан, через 3 с
  `Tap "shop.buy.mat_check" Button` — кнопка найдена, проверка перекрытий пройдена, событие синтезировано.
  Дальше 5 с ожидания «Куплено» впустую. Снимки `ui-68-shop` и `ui-68-shop-bought` совпали байт в байт
  (один и тот же payload в xcresult): ни «Куплено», ни строки отказа, ни нового баланса — нажатие до кнопки
  не дошло. Лавка — лист поверх листа автомата (`ScrollView` в `.sheet` внутри `.sheet`): одиночный
  синтезированный тап изредка забирает жест листа/прокрутки. Приложение тут ни при чём: в коде покупки
  каждый исход виден (купили — «Куплено» и баланс, отказ — красная строка `shop.refusal`).
- **Починка теста.** Ждём именно эту кнопку нажимаемой (`waitHittable`, 10 с), пауза 0,5 с, и жмём общим
  хелпером `tap(_:expecting:name:)` с одним повтором; ожидаемый результат — «Куплено» на этой же кнопке
  (`identifier == shop.buy.<id> AND label CONTAINS "Куплено"`), а не любой «Куплено» на экране. Повтор
  безопасен: проданное ядро не продаст второй раз (`ShopDaily.buy` → `sold`), а кнопка «Куплено» выключена.
  При провале сообщение говорит подпись кнопки и текст отказа, а снимок `ui-68-shop-buy-retry` показывает
  экран перед повтором.

## Проверено, багов нет

- **Экономика.** `ShopDaily.buy` (витрина, продано, есть, не хватает — всё внутри `mutate`), капсулы, дом,
  кухня, привычки, трюки: двойная покупка и минус в кошельке не проходят; кухня и привычки мёртвому не платят.
- **Сейв.** Кэш `PetStore` (волна 26) — ключ inode+время+размер, своя запись обновляет кэш, атомарная запись
  чужого процесса даёт новый inode; порча/пустой файл — копии `bak`/`prev`.
- **Время.** `catchUp` при откате часов > 5 мин ничего не догоняет, `settleFutureMarks` прижимает метки
  из будущего; `Brush.adopt` не верит меткам из будущего.
- **FeelGate и часы назад.** `Feel.now` — `systemUptime` (монотонные), перевод часов кулдаун не ломает.
- **Swift 6.** Пакет и Xcode-проект собираются в языковом режиме Swift 6 (строгая проверка — ошибки); сборка
  чистая, 0 предупреждений. `nonisolated(unsafe)`-статики (`ClipTable.shared`, `ChoreoPath.body`) пишутся и
  читаются только с главного потока (PetStage/PetChoreo под `@MainActor`).
