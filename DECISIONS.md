## Решения этапа 1
### Сборка и подпись → RESEARCH/01
- **XcodeGen + GitHub Actions `macos-26`**, сборка без подписи → ad-hoc `codesign` с entitlements (сначала appex, потом app) → `.ipa`. В entitlements только `application-groups`.
- **Установка: Sideloadly** с Windows (первый раз по USB, дальше продление по Wi-Fi). Запасной — Impactor. SideStore — только эксперимент (0.6.4 сломан, на iOS 26.4+ проблемы).
- **ID группы ищем в рантайме** (`ALTAppGroups` → embedded.mobileprovision → запасной), проверка через `containerURL`.
- **Live Activity только с `pushType: nil`.**
- Риск октября 2026: у сайдлоадеров ошибки входа Apple ID (-80045/503) — следить за версиями.
- Приватный репо: ~200 macOS-минут в месяц бесплатно (20–40 сборок). Запас — Codemagic.

### Возможности iOS → RESEARCH/02
- **3D на RealityKit** (SceneKit в iOS 26 устарел). Godot/Unity не берём: виджеты/остров/интенты всё равно на Swift.
- **Состояние считается от времени, а не тикает**: виджет, остров, уведомления и ПК показывают одно и то же.
- **Остров без пушей**: кнопки — `LiveActivityIntent` (код в процессе приложения), перезапуск каждые 8 ч из фона (действие уведомления / интент).
- **Виджет показывает готовые кадры** (PNG с альфой — иначе в тонированном Liquid Glass белые силуэты), рендерит их приложение, пока открыто; GPU в фоне запрещён.
- **Уведомления**: держать запас ~50 из 64 по прогнозу шкал, пересчитывать при каждом пробуждении.
- **Привычки**: CMPedometer, HealthKit (проверить на бесплатной подписи), CLMonitor, автоматизации «Команд», которые Вадим собирает руками по нашей инструкции.

### Сервер → RESEARCH/05
- **Отдельный воркер `pet-sync`** на аккаунте Блок Дуо; Блок Дуо не трогаем.
- **DO `Account` на владельца** (питомец, журнал, кошелёк, инвентарь, передержка) + **D1** (друзья, коды, рекорды, конфиг, аналитика). KV под состояние не берём.
- **Синхронизация журналом действий**, шкалы пересчитываются по времени, целочисленная математика + общие тест-векторы Swift/сервер.
- **Время и рулетка — на сервере**; смерть считает таймер DO даже офлайн, с окном для запоздавших действий и ручным воскрешением при баге.
- **Без паролей**: ключ P-256 на устройство, виджету — токен только на чтение, вход по инвайт-коду.
- WebSocket — только с гибернацией.
- Открыто: R2 может требовать карту; `workers.dev` может не открываться у друзей в РФ.

### Стиль и ассеты → RESEARCH/03
- **Стиль держится на текстурах**: 500–3000 треугольников + фото-шерсть 128–256 px с «мылом». Бесплатные модели почти все без текстур → основная арт-работа — перетекстуривание.
- **Предложение: направление B «Petz / Sims 2 Pets PS2»** + ползунок «Ретро» (B → C «мемный PS1»). A «Nintendogs» — запасной. **Вадим выбрал A** (16.10, см. ниже).
- **Четвероногие на скелете Quaternius (CC0)**: Shiba/Husky/Wolf с общим скелетом и 13 анимациями; «сидеть» и «спать» доделать в Blender.
- **Семейства скелетов**: quadruped / biped (Mixamo, тунг-тунг-сахур) / blob, общие сокеты (голова, шея, спина, хвост, лапы) + карта костей на модель. Шапки — на все, костюмы — внутри семейства. Крепление на кость — своя система (в RealityKit нет).
- **AI-генерация 3D** только для формы (персонажи-мемы, шмотки, мебель); риг — с готового скелета. Бесплатные Meshy/Tripo → строка в титрах (CC BY).
- **Конвертация на Windows**: Blender CLI → USDZ, все клипы на одной дорожке + `clips.json`. Запас — GLB через VRMKit.
- Ретро-эффекты: `CustomMaterial` (snapping, квантование, туман) + `PostProcessEffect` iOS 26 (низкое разрешение, дизеринг).

### Геймдизайн и экономика → RESEARCH/04, config/economy.json
- **Смерть** только после настоящего забвения: брошенный питомец умирает через ~58–69 ч; 3–4 захода в день сердец не теряют. 5 сердец (6 с лучшей будкой), ночью сердца не падают, последнее сердце — 8 ч «последнего шанса», и не в первые 3 ч после пробуждения.
- **Три уровня предупреждений** (Просит / Плохо / Критично) — только локальными уведомлениями по прогнозу, ночью тихо.
- **Отпуск**: передержка у друга до 7 дней (друг получает монеты) или гостиница за монеты до 14 дней.
- **После смерти** — альбом и могилка, монеты/дом/гардероб остаются; питомец 30+ дней передаёт черту следующему.
- **Валюты**: монеты, билеты (капсулы), лоскуты (из дублей, у портного). Редкости 70/22/7/1 %, гарант эпика каждые 15 и легендарки каждые 60.
- **Доход**: активный ~310 монет/день чистыми, ленивый ~65; улучшения дома (6 линий × 3 уровня) у активного ~6,5 мес.
- **Анти-инфляция**: траты 0,7–1,05 от дохода за 7 дней; рычаги — цены улучшений, расходники, износ игрушек, ярмарка, сезонные вещи.
- **Друзья без пушей**: подарки «едут» 1–3 ч с известным временем прибытия → локальное уведомление; уровни дружбы 1/7/30/90 дней.
- **Блок Дуо** — своя мини-игра в приложении, без браузера и сервера (волна 12, см. ниже).

## Решения Claude без Вадима: открытка дня (19.10.2026, волна 10, можно откатить)
- **Кадр — снимок 3D-сцены, не камера телефона.** У RealityView своего снимка нет (форумы Apple, ImageRenderer даёт белое), поэтому `PostcardCamera` пробует по порядку: ARView из окна → вид с CAMetalLayer (drawHierarchy) → окно целиком. Одноцветный кадр не считается. Кадр 4:3 вокруг пса (центр — 0,53 высоты экрана), JPEG 512×384, качество 0,8, в `Paths.dir/photos`. В сейве только имена файлов (`shots`, `Postcard.image`).
- **Когда снимаем**: через 1,6 с после кормёжки/лакомства, игры, ласки, купания и трюка (трюк = «играли»), через 4,5 с после возвращения с находкой. Только если сцена на виду: никакой лист не открыт, пёс жив и не спит/не дремлет/не гуляет/не при смерти. «Лечение», «разбудил», шаги не снимаем — некрасивые моменты.
- **Сколько**: до 3 кадров на день, не больше 8 снимков в день, между снимками 15 мин. В пределах паузы лучший момент другого вида заменяет только что снятый; когда три кадра есть — новый вытесняет худший, если он ценнее (очки как у моментов открытки).
- **Какой кадр у открытки**: кадр того же дня и вида момента (кормёжка ↔ лакомство, находка ↔ первая находка), ближайший по времени; нет — лучший кадр дня; нет кадров — прежняя мордочка. Эмодзи находки поверх фото не рисуем: на фото пёс и так с находкой.
- **Уборка**: кадры прошлых дней уходят из `shots` при раздаче открыток; файл без ссылки (открытка пропала, выброшена, удалена из альбома) удаляется при следующем запуске или изменении альбома, но не раньше 10 мин после записи.
- **Срок**: несохранённая открытка живёт до конца 7-го дня после своего (как и было). Под кнопками лист пишет «Не сохранишь — пропадёт через N дней»; в последние сутки — «Сегодня последний день: сохрани, а то пропадёт.» акцентным цветом с часиками, а на чипе главной «· последний день». Уведомление не шлём: мягко, без давления.

## Волна 10: «Расчесать» в ядре, бафф «Лови мячик» (Claude, 19.10.2026, можно откатить)
- **«Расчесать» — действие ядра** (`care.actions.brush`, TS и Swift, векторы `brush_misc`/`brush_unwell`). Эффект прежний: ласка — половина «Погладить» в том же состоянии (с множителями и потолком 100), монет нет. Жест, 8 мазков и стадия шерсти остаются в приложении.
- **Откат 6 ч живёт в ядре**: `care.cooldowns_min.brush = 360`, ключ `cooldowns["brushing"]` (id `brush` занят расчёской из магазина). Отказы: умер → гуляет → нет в конфиге → ванна → спит → беда (L3) → откат. Беда раньше отката, как у трюков.
- **Старые сейвы**: `BrushLog` (t, n) пишется как раньше. Если в ядре отката ещё нет, а `brush.t` был меньше 6 ч назад, откат берётся из него (Brush.adopt). В журнале теперь `act.brush` вместо `brush`, шерсть читает обе записи. Поэтому расчёсывание видно в «Пока тебя не было» и засчитывается доброй утренней открыткой, а монет за него по-прежнему нет.
- **Часы назад**: как у «Погладить»: ядро ждёт, пока время питомца пройдёт откат; остаток на экране не больше 6 ч.
- **Бафф дома `minigame_coins_x` к «Лови мячик»** («Игровой комплекс» ×1,1, «Батут и горка» ×1,15): монеты = round(сырые × убывание по номеру раунда × бафф), округление один раз в конце. **Дневной потолок 60 бафф не поднимает**: с баффом до него доходят быстрее (меньше раундов на неполных очках), но больше 60 монет за игру в сутки не заработать — доход активного игрока не растёт. Бафф читает приложение через `PetEngine.mods`, ядро его по-прежнему не применяет. В «Доме» у линии «Игровой уголок» появилась строка «Монет за «Лови мячик» на 10%/15% больше».

## Свет комнаты, волна 10 (Claude без Вадима, 19.10.2026, можно откатить)
- **«Комната вечером» по умолчанию — «По времени»**: после заката (18:00–19:30) тёплый вечер с лампой, за 30 мин до «Ложусь в» и до +15 мин (тогда засыпает Шиба) — переход в ночной синий полумрак с луной в окне, через час после подъёма — снова день. ## Волна 11: режим сна владельца (Claude без Вадима, 19.10.2026, можно откатить)
- **Что считается касанием**: вход в приложение и уход в фон, кнопки виджета, острова, пульта и уведомлений. Шаги и «Команды» — нет: шаги приходят сами, команду может запустить автоматизация по расписанию, пока хозяин спит.
- **Оценка** (`app/Shared/OwnerSleep.swift`): вечер — последний заход 18:00–04:00, утро — первый 04:00–14:00, 14:00–18:00 о сне не говорит. Ночь от 3 до 14 ч, иначе не в счёт. Окно — медиана за последние 14 дней с отбросом значений дальше 3 ч от медианы, округление до 5 мин. Пока полных ночей меньше 5 — 00:00–08:00. Время местное на момент касания: переехал в другой пояс — окно не съезжает. Ночи храним 21 день. Сейв — верхнее поле `sleep`, пустое не пишется, в новый щенок переносится (это привычки хозяина).
- **Тихие часы уведомлений** — объединение сна питомца («Ложусь в» – 07:30) и окна хозяина, но не дальше 3 ч (`no_death_first_h_after_wake`) от окна питомца. Исключения «умирает» в ядре нет: всё из тихих часов переносится на их конец. С пределом 3 ч «последний шанс» всегда приходит раньше смерти (до тихих часов таймер съест ≤ 3 ч, после подъёма — тоже ≤ 3 ч, 3 + 3 < 8). Поэтому по умолчанию тихо теперь до 08:00, а не до 07:30. Ядро не тронуто: тихие часы — существующие `quietFromMin/quietToMin`; «Вернулся!» с прогулки тоже молчит в этом окне.
- **Сон пса окно хозяина сам не двигает**: `owner.bedMin` по-прежнему задаёт только хозяин. Кнопка «Отбой» как была (лампа 20:00–02:00). Если выучено, что хозяин ложится заметно иначе (≥ 20 мин): за 15 мин до его «засыпаю» и до 45 мин после пёс раз за вечер говорит «Отбой?»-фразу, а в настройках есть кнопка «Ложиться вместе со мной: 00:40» — она ставит «Ложусь в» (прижато к 20:00–02:00).
- **«Доброе утро»** — раз за ночь, при первом заходе 04:00–13:00 после перерыва ≥ 3 ч (не всенощное бдение и не первый запуск). Говорит пёс фразой на главной (8 с), только если он жив, дома и не спит; спал — поздоровается на следующем заходе этим утром. Под «Пока тебя не было» фраза ждёт закрытия отчёта.
- **Настройки**: между «Лампа» и «Комната вечером» — «Я сплю примерно 00:40–08:10» и статус («учится сам», «задано вручную», «пока учусь: 2 из 5 ночей»). Экран «Я сплю»: «Засыпаю» 18:00–04:00 и «Просыпаюсь» 04:00–14:00 (тронул — окно ручное), «Учиться самому», «Забыть выученное» (с подтверждением).

## Волна 11: характер и память (Claude без Вадима, 19.10.2026, можно откатить)
- **Память — одна запись на событие** (`SaveFile.memories`, `Memories.swift`): знакомство, первая прогулка (с её находкой), первая находка каждого вида, трюки (самый ранний — «первый»), рекорд «Лови мячик» (одна запись, правится при новом рекорде), первая вещь из автомата, последний купленный уровень каждой линии дома, дни вместе (вехи дружбы из Postcards.friendDays) и дни рождения (каждые 365), любимые вкусы. Разбирается в PetStore после каждой записи, журнал — по seq, один раз.
- **«Первое» только наверняка**: старый сейв, где ранние прогулки или крутки уже ушли из журнала, «первой прогулки» и «первой вещи» задним числом не получает (сверка счётчиков в состоянии с записями журнала). Рекорд, перешедший от прошлого щенка, — база, не воспоминание. Новому щенку память и характер не переходят.
- **Характер — три оси**: игривый ↔ спокойный (доля игр и прогулок), ласковый ↔ сам по себе (доля поглаживаний), чистюля ↔ сорванец (доля ванн и расчёсываний). ## Волна 12: Блок Дуо (Claude без Вадима, 19.10.2026, можно откатить)
- **Своя игра вместо веб-версии в браузере**: правила из block-duo (поле 8×8, тройка фигур, полная строка или столбец исчезают, комбо), но всё на устройстве, в `Shared/BlockDuo.swift`, без сервера. Партия детерминирована по сиду: раздача тройки и фигура Шибы — от сида и номера хода, тесты и снимки повторяемы.
- **«Дуо» — это Шиба**: после каждой тройки (когда ты поставил три фигуры) он ставит свою маленькую фигурку (точка, палочка 2–3, уголок, квадрат 2×2). Выбирает просто: где уберётся больше линий, при равенстве — где больше соседей (ставит «к куче», а не в угол). Некуда — пропускает ход, это не конец партии. Его клетки рыжие с лапкой, последний ход обведён. **Счёт общий**, на итоге видно «Ты N · Шиба M».
- **Очки** (как в веб-версии): клетка фигуры — 1 очко; n линий за ход — 40·n·(n+1)·комбо; чистое поле — +500. Комбо растёт с каждым ходом с линией (и ходы Шибы в счёт) и гаснет на третьем ходу подряд без линий. Партия кончается, когда ни одна фигура тройки никуда не встаёт.
- **Монеты — механизм мини-игр**: ключ `minigames.list.blockduo` в economy.json (base 5, max 40, par_score 3000, свой потолок 60 в сутки), убывание за день как у «Лови мячик» (1–6-я партия ×1, 7–12-я ×0,5, дальше ×0,2), бафф монет мини-игр тоже действует. **Общий потолок мини-игр** — `minigames.daily_cap` 60: мячик и Блок Дуо вместе за сутки не дадут больше 60. par_score 3000 — потому что жадный автопилот набирает ~25 000 за партию, а живой игрок слабее; 3000 — «нормальная партия».
- **Рекорд и счётчики в сейве**: `blockduoBest`, `blockduoDay`, `blockduoCoins`, `blockduoGames` (верхний уровень, пишутся только если не ноль, новому щенку переходят — рекорд хозяина, а не собаки). Партия с очками — это «Поиграть» в ядре (настроение, уход), как у мячика.
- **Вход — одна кнопка «Мини-игры»** на месте мячика: меню «Лови мячик» / «Блок Дуо». Седьмой кружок в ряд на iPhone Air не влезает. Ещё открывается по pet://blockduo.
- **Экран**: фигуру тащишь из тройки, на поле она висит на 76 pt выше пальца (палец не закрывает место); место подсвечено цветом фигуры, линии, которые исчезнут, — светлее с жёлтой рамкой. Ход идёт на экран по шагам: легла → линии вспыхнули → исчезли → «Шиба думает…» → его фигура. Хаптика: щелчок при «встала на место», успех на линии, предупреждение при сбросе мимо.
- **Закрыл посреди партии с очками — партия засчитана** (монеты по текущему счёту), чтобы долгая игра не пропала.
- **После партии в комнате**: экран закрылся — Шиба подпрыгивает и виляет (`BlockDuo.reactKind`), говорит фразу по итогу (рекорд, «видел, как я линию убрал?», просто «классно сыграли вдвоём»).

## Волна 12: свои персонажи (Claude без Вадима, 19.10.2026, можно откатить)
- **Формат — папка `<имя>/`**: `character.json` и модель (`model.usdz` по умолчанию, можно `.usdc/.usda/.reality` через поле `model`). В модели скелет и **одна анимация-таймлайн**, клипы — куски этого таймлайна в секундах, как у Шибы (`shiba.clips.json`). Разбор и проверка — `CharacterPack.swift` (чистая логика, тесты `CharacterPackTests`), хранение — `CharacterStore.swift`, сцена — `PetModel.load(character:)`.
- **character.json** (обязательны только `name` и `clips`, остальное — как у Шибы):
  - `format` — 1; `name` — имя в списке и тостах; `author`, `license` — строка под именем (CC0, CC-BY и т. п. — на совести автора папки);
  - `model` — файл рядом, по умолчанию `model.usdz`; `fps` — по умолчанию как у Шибы;
  - `scale` — множитель к росту Шибы 0,42 м (0,25…3); `lift` — подъём над полом в метрах (−0,3…0,3); `yaw` — поворот в градусах, если модель смотрит не на +Z;
  - `clips` — `{"имя_в_файле": {"start": 0, "end": 3.3, "loop": true}}`; `loop` можно не писать — для idle/walk/gallop/sit/lie/sleep цикл и так;
  - `rename` — наш клип → клип в файле: `{"idle": "Idle_Breath"}`; без записи ищем клип с нашим именем;
  - `bones` — `{"body", "head", "neck", "back": [...]}`: на каких костях едут шапка, шарф, плащ и взгляд; не заданы — ищем кости Шибы;
  - `color` — `"#RRGGBB"`, основной цвет шерсти; `deathShift` — сдвиг лёжа на боку в единицах модели (у Шибы −1,36; нет — 0).
- **Пример**:
  `{"format": 1, "name": "Серый Шиба", "author": "…", "license": "CC0", "scale": 0.8, "color": "#8B8F99", "rename": {"idle": "Idle"}, "clips": {"Idle": {"start": 0, "end": 3.33}, "walk": {"start": 3.33, "end": 4.33}, …}}`
- **Обязательные клипы — 7**: idle, walk, eat, sit, lie, sleep, death. Без любого пак не ставится, причина по-русски («нет клипа idle — без него пёс не стоит»). **Необязательные — 25** (остальные клипы Шибы): нет — пропадает только своё движение, список «чего не будет» виден под паком («не зевает», «садится рывком, без перехода»). idle_2 и idle_headlow без своих играют idle, gallop — walk. Режиссёр и так пропускает шаги без клипа (PetStance.pick), поэтому лишних заглушек в сцене нет.
- **Ошибки — не падение**: битый JSON (с полем, где сломалось), кусок с конца раньше начала или за таймлайном, rename на несуществующий клип, scale/lift вне пределов, нет файла модели, странное расширение, кривой цвет. Пак с ошибками всё равно копируется и лежит в списке с причинами красным — его видно и можно заменить исправленным. Поставить его нельзя.
- **Импорт** — «Настройки» → «Свой персонаж» → «Добавить из «Файлов»» (fileImporter: папка целиком или файлы из неё, character.json среди них). URL чужие: `startAccessingSecurityScopedResource` на время копирования и `stop` в defer. ## Волна 14: время и сутки (Claude без Вадима, 19.10.2026, можно откатить)
- **Один ключ дня — `DayKey` (Shared/DayKey.swift).** Номер местных суток = floor((минута UTC + сдвиг пояса на этот момент) / 1440), летнее время учтено. Через него идут все дневные счётчики: потолок ухода, привычки, «Лови мячик», «Блок Дуо», «Щенок против зомби», общий потолок мини-игр, кухня, капсула, витрина лавки. - **Полночь.** Ядро шагает целыми минутами, поэтому pet.t отстаёт от now до 59 с. Действие теперь пишется в журнал моментом `max(now, pet.t)`, а не временем питомца. Нажатие в 00:00:20 — это уже новые сутки и новый потолок. Ядро не трогали.
- **Шкалы — по абсолютному времени, календарь — только для лимитов.** Убывание, сон, прогулки считает ядро в unix-секундах. Смена пояса и перевод на летнее время их не двигают: осенний час 03:00→02:00 — это не «часы назад», `clock_back` не пишется, четыре часа шкал за четыре настоящих часа.
- **Сохранённый день назад не откатывается** (уже так было у потолков и витрины, теперь у всех через `DayKey.today/newer`):
  - часы назад или перелёт на запад не дают второй потолок — счётчики остаются, пока календарь не перейдёт сохранённый день;
  - часы вперёд или перелёт на восток — сутки сменяются раньше, как у хозяина. Туда-обратно выходит ноль: «лишние» сутки потом уже засчитаны;
  - часы вперёд — это прошедшее время: шкалы проживают прыжок (ядро не знает, что часы врут). Назад — питомец ждёт, пока время догонит (`clock_back`, как раньше).
- **Трюки и кухня при часах назад.** Метки «последний раз» из будущего (перерыв трюка, ласка от трюка, перерыв кухни) в `catchUp` прижимаются к now. Прогресс трюков и дневные счётчики не сбрасываются, но перерыв (1 мин, ласка 3 мин) идёт заново от «сейчас». Бесплатной удачи нет: в волне 13 откат давал засчитанную попытку сразу. Кухня не стоит закрытой, пока часы не догонят.

- **Склонения** — только `EconText.plural`: `AwayBuilder.times`, `ZombieRun.friendsText`, Guides (сердечки, дробные — «0,5 сердечка» в `heartsWord`), Memories (годы, дни). Своих копий больше нет.
- **Тесты** — `TimeDayTests` (Linux): полночь ±1 с в пяти поясах, первая и последняя секунда суток, привычки и мини-игры в полночь, часы назад и вперёд, перелёт ±12 ч, Белград 29.03 и 25.10.2026. Баланс (`config/economy.json`) не тронут.

Поэтому имя ставится только в именительном и только там, где рядом нет слов мужского рода; в остальных местах — «питомец» в нужном падеже («Очки питомца», «питомец отряхнулся»). ## Волна 15: надёжность сейва (Claude без Вадима, 19.10.2026, можно откатить)
- **Щенок умирает только от забвения.** Сбой записи, обрезанный файл или порча больше не заводят нового щенка, если есть хоть одна целая копия.
- **Копии.** Перед каждой записью прошлый валидный `state.json` кладётся в `state.bak.json`. `state.prev.json` пишется, как раньше, раз в 10 записей, плюс зеркало приложения в Documents. Порядок восстановления: bak → prev → зеркало. Запись атомарная (временный файл + переименование): если места нет, бросается `writeFailed`, а старый файл цел. Ошибка записи bak не мешает основной записи.
- **Читатель ничего не двигает** (`read`, виджет, Live Activity). Он отдаёт копию в памяти. Чинит диск только `mutate`: испорченный файл откладывается в `state.broken-<t>.json`, в журнал пишется `save_restored` (key — имя копии), в приложении всплывает тост. Раньше `read` сам перекладывал битый файл, и следующий `mutate` молча заводил щенка с нуля.
- **Испорчено всё** (основной файл и все копии) — ничего не стирается. `state*.json` переносятся в папку `corrupt-YYYY-MM-DD-HHMM` (UTC) рядом. Только тогда заводится новый щенок, в журнале — `save_corrupt` с именем папки, тост «Сохранение повреждено, копий нет: файлы отложены в …». Читатель в этом случае бросает `corrupted`, а не «первый запуск».
- **Файл есть, но не читается** (защита данных до первой разблокировки, ошибка ввода-вывода) → `unavailable`. Ничего не трогаем, ждём следующего раза.
- **Расширения щенка не заводят.** Виджет, интенты и Live Activity (`Bundle.main` — `.appex`) получают `mayCreate = false`: на пустой папке — `noSave`, на всём битом — `corrupted`. Новый щенок и карантин — только в приложении. Чинить из копии расширениям можно: это тот же щенок.
- **Координация.** Как была: `NSFileCoordinator` на `state.json` (чтение, запись `.forMerging`) плюс `NSLock` в процессе. Все копии, bak и карантин правятся внутри той же координации записи, чтение и запись короткие и синхронные. Своих замков-файлов не добавлял.
- **Миграции.** `app/Tests/Fixtures/save-v0.7…v0.14.json` — один синтетический сейв (`fixture-pet`, без личных данных), записанный `SaveFile` каждой эпохи: `git archive` коммита сборки, swift test в WSL. `SaveMigrationTests` проверяет, что текущая версия читает каждую эпоху без потери щенка, монет, предметов, трюков, рекордов и открыток, и ни одно поле старого файла не пропадает при перезаписи. Все эпохи прошли без правок декодеров.
- **Пояс рождения.** `SaveFile.birthTz` — необязательный, nil не пишется. `bornDay` — сутки `DayKey` в этом поясе. От него считаются дни вместе и дни рождения (Memories, вехи открыток), так что перелёт дату не двигает. Новый щенок получает пояс телефона. Сейв старше волны 15 получает пояс при первой записи (пояс телефона на момент рождения, с учётом летнего времени), один раз. `startOver` — свой пояс у нового щенка. Окно открыток (`refresh`, `hasUnsettledDay`) и «день жизни» правил не трогал — это не день рождения.
- **Тесты** (Linux): `SaveRecoveryTests` (обрезанный JSON, нули, пустой файл, всё битое, расширение, недоступный файл, нет прав на запись, bak = прошлая запись), `SaveMigrationTests`, `BirthTzTests`. Баланс не тронут.
- **Не делал:** словари `TasteLog.seen/opened`, `econ.items`, `tricks.items` и массив `memories` декодируются целиком. Одна битая запись внутри валидного JSON обнулит весь словарь. При атомарной записи такого не бывает, поэтому не трогал (журнал и открытки уже Lossy). NaN или бесконечность в числе ломает кодировщик: файл цел, но запись перестаёт проходить (`writeFailed`). Такого не встречалось, не трогал.

Под мини-играми и «Пока тебя не было» комната рисовалась на 60 fps: три направленных света, тень key-света, скиннинг, системы ECS. Теперь через 0.8 с после открытия обложки подставка с Шибой и комната выключаются (`isEnabled = false`): не рисуются и не анимируются. При закрытии включаются сразу, до того как обложка уехала, — прыжок после игры виден. Если цикл позы за паузу остановился, `ClipPlayer.wake` его перезапускает. Под листами (.sheet) не гасим: из-под них видна полоска комнаты, на .medium — половина. Фото открытки под обложкой и так не снимается (`sceneClear`).

Теперь шаг времени идёт, только когда scenePhase == .active. На паузе раунд стоит, кадр не рисуется, цикл просыпается раз в 1/4 с. В фоне iOS и так замораживает приложение.
- **30/60 fps не делал.** У RealityView нет публичного способа задать частоту кадров или рисовать по запросу (у ARView и SCNView было). В Info.plist нет `CADisableMinimumFrameDurationOnPhone`, так что на ProMotion потолок и так 60 Гц. Обходы через внутренние слои — риск на ревью и поломки в новой iOS, не трогаю.
- **Свет и тени без изменений.** Три направленных света и лампа (днём выключена). Тень только у key-света (`maximumDistance` 4), пол и стены теней не отбрасывают, под псом — пятно-текстура 128 px. Это уже экономно, а убрать тень — видимая разница.
- **Таймеры в порядке.** Тикер AppModel — раз в 30 с, в фоне стоит. TimelineView: виньетка и подложка статус-бара — 30 с, таймер нужды — по границам минут, лавка — 60 с. Звук: AVAudioEngine стартует лениво, глушится через 30 с тишины и в фоне. Live Activity обновляется не чаще раза в 5 с и только при новом содержимом, перезапуск через 7 ч. Виджет: следующая запись по прогнозу, не позже чем через 12 ч; `reloadAllTimelines` из приложения на переднем плане в бюджет WidgetKit не идёт.
- **Память в порядке.** Кеши ограничены: клипы (AnimationResource по ключу), контроллеры ≤ 8, меши шерсти ≤ 8, текстуры шерсти ≤ 16 (по стадии и цвету), материалы ≤ 64. Текстура пола собирается раз на сцену. Задачи AppModel держат self слабо. Сцена пересобирается только при смене персонажа (`.id`).
- **Не делал.** Склейку `afterChange` (виджет, остров и уведомления после каждого действия): те же функции зовут интенты виджета, и отложенная работа там пропадёт при выходе процесса, а выигрыш мал. Пул буферов растеризатора зомби: ~2 МБ на кадр выделяются заново, но это дешевле самого растра, а пул между потоками — лишняя сложность.

## Волна 17: тексты (Claude без Вадима, 19.10.2026, можно откатить)
- **Названия в тексте — после двоеточия, со строчной, в именительном.** Склонять названия из данных (еда, вещи капсул, блюда, свои персонажи из пака) значит хранить формы для каждого и угадывать их для чужих паков. Проще и надёжнее переставить фразу так, чтобы именительный стоял к месту, — так уже написаны строки lines.json («Выпало: {item}», «Трофей: {item}»). Тост покупки: «Угостили: Морковка» → «Угощение: морковка за 3 монеты»; строка рецепта: «Нужно: Тыковка из капсул» → «Нужна вещь из капсул: тыковка»; VoiceOver кнопки «Угостить» тоже со строчной; кнопка «Дом»: «Купить Тёплая будка, …» → «Тёплая будка: купить за …». Общий помощник `EconText.lowerFirst`. Винительный там, где он уже есть в данных (`Finds.acc`, `Tastes.acc`), не трогал.
- **Имя питомца после глагола — через `PetNames`.** Статус для Siri (`Presenter.statusText`) у мёртвого питомца говорил «Шиба больше нет с нами» — теперь `PetNames.gone`: «Шибы больше нет», у своего персонажа «Мурка больше не с нами». Уведомление о конце подписи «чтобы не потерять Шиба» → «…не потерять Шибу», у своего персонажа «питомца» (`PetNames.adapt`, склонять чужое имя не пытаемся).
- **Числа со словом — новые подстановки `{times}` и `{days}`.** «Поймал {count} раз подряд» давало «Поймал 3 раз», «{count} дней вместе» — «21 дней». Теперь код подставляет число вместе со словом в нужной форме (`EconText.times`, `EconText.days`), строки пишут «Поймал {times} подряд!», «Мы вместе уже {days}.». `{count}` остался для голого числа («Рекорд — {count}!», «{count}-й день»). Поправлены 6 строк: `w.memory_record.03`, `w.memory_days.02`, `a.card_pets.01/02`, `a.card_days.01/03`. Тест не даёт снова написать «{count} дней/раз/лет…». Тост «Зомби: 1 очков» → `EconText.points` («1 очко», «3 очка»).
- **Кухня: фраза пса одна.** После блюда фраза («Шиба уплетает…») шла в пузырь и тут же, вместе с бонусом, в тост — одна мысль дважды. Пузырь оставил (это голос пса, он же в UI-тесте), тост теперь только про бонус: «Подарок за первое блюдо дня: +15 монет» (`Cooking.bonusText`, вместо `Cooking.reply`). Без бонуса тоста нет. ## Волна 26: плавность

- **Сначала замер, потом правки.** `PerfUITests` (4 теста, 3 итерации): холодный запуск, лист «Шкалы», тап
  «Покормить» + 3 с анимации, 5 с покоя. Порогов (baseline) нет — медленный раннер не должен ронять CI; тест падает,
  только если сценарий сломался. xcodebuild идёт с `-quiet`, поэтому шаг «Perf metrics» достаёт числа из xcresult
  (`xcresulttool get test-results metrics`) и печатает строки `PERF …`; полный JSON — `perf-<шард>.json` в
  Pet-xcresult. Числа до/после — в RESEARCH/13-perf.md.
- **Стор держит последний разобранный state.json в памяти — по отпечатку файла.** Отпечаток — inode + время
  изменения + размер. Атомарная запись (наша, виджета, интента) — всегда новый inode, запись на месте — новое время и
  размер; любое расхождение — читаем и разбираем с диска, как раньше. Отпечаток снимаем до чтения: подменят файл между
  ними — в кэше окажется старый отпечаток, и следующий вызов прочтёт заново. Порча, пропажа файла, `wipe` — кэш
  сброшен. После своей записи кладём байты, а разбор — лениво, при первом чтении. Итог: тап был ~5 разборов JSON
  (read → mutate → refresh → afterChange → уведомления), стал 1; запуск — с ~6–8 до ~3.
- **Не доверяем «своей» копии SaveFile в памяти без проверки файла.** Проще было бы держать f после mutate и не
  смотреть на диск, но виджет и интенты пишут из другого процесса — без отпечатка приложение затёрло бы их правку
  своей старой копией. Проверка — один `stat`, он на порядки дешевле JSON-разбора.
- **Сцена не ищет комнату по всему дереву на каждом кадре.** `findEntity(named: "room")` / `"bowl"` / `"ball"` /
  `"food"` в хореографии звались каждый кадр. Теперь `PetChoreo.sceneRoom(of:)` и `roomPart(_:_:)` помнят найденное
  (слабой ссылкой) и перед выдачей проверяют: имя то же, сущность всё ещё под тем же родителем/в той же сцене. Не
  совпало — ищем заново, так что снятую/заменённую миску и комнату нового персонажа видим сразу.

## Волна 29: отклик

Вибрация и звук от действий пользователя — одна точка `Feel` (app/App/FeelKit.swift), правила «когда молчать» —
`FeelGate` (app/Shared/Feel.swift, тесты на Linux — FeelTests). Опись «было → стало» — RESEARCH/15-feedback.md.
Вид, тексты и баланс не трогали.

- **Семь видов вместо четырёх.** Было light/medium/success/warning через счётчики модели и `.sensoryFeedback` на
  главном экране. Стало `select`, `tap`,
  `soft`, `bump`, `nudge`, `success`, `denied` на генераторах UIKit: у них есть `prepare()` и интенсивность, а
  слой-счётчик больше не нужен (`HapticsLayer`, `BuzzKind`, `buzzes` удалены). Звук действия передаётся тем же
  вызовом: `Feel.success(.hearts)`.
- **Один отклик на одно нажатие.** Кнопки ухода давали «тик» на нажатие и «получилось/нельзя» через миг — ядро
  отвечает за миллисекунды, два отклика сливались в дребезг. Теперь только итог (`settle`). То же у покупок в
  доме, кухне, автомате, «Расчесать», последнего мазка, «Зомби» (конец раунда и карточка итога).
- **Тап при нажатии — только когда итог заметно позже:** трюк (итог после анимации), капсула (падает и
  открывается), готовка (пёс ест через 350 мс), «Отбой», «Готово». Если итог в том же тике — без тапа.
- **Навигация молчит:** открыть/закрыть лист, ✕ в мини-играх, кнопка автомата, «Кухня». Отклик — ответ на
  действие с последствием, а не на переход. Системные тумблеры и пикеры — своим системным откликом.
- **Отказ не бывает немым.** `AppModel.refuse(text)` = `Feel.denied()` (warning + «не-а») + красный тост; им
  заменены все `show(…, ok: false)` (ошибки хранилища, вещи, персонажи, открытки, плашка «нечего делать»).
  Серые карточки (трюки, «Расчесать», «Куплено» в лавке) — `.deniedTap(when:)` после `.disabled`: прозрачная
  накладка только у запертой, тап по ней даёт `denied`, вид не меняется. Не `.onTapGesture` на самой кнопке: на
  живой Button он перехватывает её действие. Прогулка «нельзя» раньше только вибрировала — теперь и «не-а».
- **Промах в игре — `nudge`, не `denied`.** Упустил кость, отпустил фигуру мимо, обнял зомби, против шерсти, трюк
  не вышел, лай не готов: это часть игры, тревожное уведомление на каждый промах — слишком громко. Звук промаха
  (`refuse`/`heartLost`/`boop`) оставлен — вопрос Вадиму.
- **Привычка «сегодня уже отмечена»** — `nudge` без звука: тост у неё дружелюбный, warning ему противоречил.
  Привычка из Siri/виджета — без звука; вибрация, только если приложение на экране.
- **Выучил трюк — один звук.** Было «динь» и арпеджио сердец разом; теперь `success` с сердцами.
- **«Зомби»: одна вибрация на кадр** — самая сильная из событий кадра (`FeelKind.strongest`), звуки событий
  остаются. Конец раунда вибрирует на последнем кадре, карточка итога через 0,9 с — только звук.
- **«Блок Дуо»: фигура встала на новое место — `select`**, а не impact: таких щелчков много подряд за один
  жест. Ход Шибы — `bump` (заметнее моего `tap`).
- **Ласка — `soft`.** Тап по питомцу, тики ласки, мазок щёткой. `prepare(.soft)` при начале касания.
- **Кулдаун по виду** (50 мс у выбора … 600 мс у отказа) и правило кадра: в 50 мс слабый или равный отклик
  после уже прозвучавшего отбрасывается, сильный проходит (тап-успех в одном кадре — только успех). Звук — 70 мс
  на сигнал, тики ласки делят ключ. Отброшенный вызов кулдаун не продлевает.
- **Фон.** `Feel.wentBackground()` в `scenePhase == .background` — ни вибрации, ни звука до `.active`.
  Фоновые отклики (`Feel.ambient`: сердца, смерть/новый щенок, «вернулся с прогулки», отзыв о вкусах) молчат
  2 с после возврата — снимок догоняет время вдали. Это правило раньше было только у звука в SoundKit, теперь
  общее для вибрации и звука, а SoundKit.ambient/settled/strokeTick удалены.
- **Настройки.** «Звук» (`sound.on`, переключатель уже есть) — `FeelGate.soundKey`, им же пользуется SoundKit.
  «Вибрация» — ключ `haptics.on`, по умолчанию вкл., переключателя нет (не меняем вид — вопрос Вадиму).
  Системный «Тактильный отклик» генераторы UIKit уважают сами. Беззвучный режим — сессия `.ambient` осталась:
  звук молчит, музыку не глушит, вибрация есть.
- **`prepare()`** там, где важна задержка первого отклика: начало касания (ласка), старт мини-игр, взял фигуру в
  «Блок Дуо», нажатие ухода (готовит success/denied), капсула после крутки.
- **Мимо Feel** — только звуки хореографии (мяч, хруст корма, тявк «Голоса» на прыжке) и «динь» переключателя
  «Звук»: это часть анимации/настройки, а не отклик на палец.
- **В тестах тишина:** `Env.isTesting` — ни генераторов, ни звука. Чистая логика — FeelTests (19 тестов, Linux).

## Волна 31: для всех

Опись по экранам — `RESEARCH/17-a11y.md`, слова и правила — `app/Shared/A11y.swift` (A11yTests, 15 тестов, Linux),
модификаторы — `app/App/A11yKit.swift`, аудит — `app/UITests/AccessibilityUITests.swift`.
- **Зрячий текст не меняется.** Всё новое — подписи, значения, подсказки, действия VoiceOver или рост шрифта только на
  крупных размерах. `petFont(n)` на обычном размере — ровно прежний `.system(size: n)`.
- **Сцена для VoiceOver:** значение — сводка «хочет …; сытость N %, …» (порядок листа шкал, без родовых слов), действия
  ухода теми же словами и вызовами, что кнопки панели; отказ — тост, который проговаривается объявлением. В UI-тестах
  значение остаётся служебным «glass=N» (HouseUITests, ожидание стекла).
- **Игры:** «Лови мячик» и «Зомби» ведут смахиванием вверх/вниз (шестая часть хода, `A11y.nudge`), значение — сторона
  словами. «Блок Дуо» с VoiceOver не сыграть (перетаскивание) — честная вежливая оговорка в описании, как и «игра
  больше для глаз» у двух других. Оговорки читает только VoiceOver.
- **Крупный шрифт:** правило волны 15 в силе — главный, панель, HUD игр, щётка в комнате, лицо открытки фиксированы;
  растут листы. Потолок `A11y.fontCap = 2×`, мельче исходного не бывает. На accessibility-размерах строки карточек
  встают стопкой (`AXRow`), лимиты строк снимаются (`axLines`), трюки — в одну колонку, альбом — в две. NeedBar
  (Shared, его собирает и виджет) растёт только в листе шкал (`grows: true`, свой `@ScaledMetric` и тот же
  потолок `A11y.scaled`); в виджете и на обычном размере — как было.
- **Reduce Motion:** пёс и его хореография двигаются всегда — это сам питомец. Спокойнее становятся необязательные
  движения: тряска отказа стоит (одна на всё, `RefuseShake`), одно сердечко вместо веера, без искр щётки,
  выпрыгивания → проявление, пружины с подскоком → easeInOut 0,2 с, без пульса «Гав». Reduce Transparency / Increase
  Contrast отдельно не трогали: системные материалы и Liquid Glass уважают их сами.
- **Аудит:** `performAccessibilityAudit(for: .all без .contrast)` на главном, листе шкал, кухне, лавке, автомате, доме, трюках, альбоме и
  заставках двух игр — четырьмя тестами по 1–4 экрана (один тест на все десять не влезал в 180 с на тест);
  отчёт по каждому экрану — вложение `a11y-audit-<экран>`. Валят тест подписи, зоны касания, трейты, элементы без
  доступности, текст, совсем не растущий с крупным шрифтом, и обрезка на AccessibilityXL. Исключения (видны в
  отчёте): 3D-сцена и игровые поля; зона касания у того, что не нажимается (строки шкал, сердечки); dynamicType на фиксированных экранах; эмодзи-значки; «частичный» Dynamic Type

## Волна 32: баланс (мягкая смерть, старт из грязи, строгость, доход)

- **Мягкая смерть — «пёс убежал»** (`Runaway`, `death.comeback`). Ядро не менялось: на последнем сердечке `alive = false`,

  с общей функцией цены из волны 32 D). Цена возвращения: 2,5 сердечка, низкие шкалы, −20 % монет «на объявления».

  или в отпуске. Насовсем: срок вышел, третий побег за 30 дней, часы переводили назад (не прощаем, ТЗ v2 п. 9).

  «Вернуть домой», «Взять нового щенка»); виджет и отчёт «пока не было» говорят «нет дома». Правила объясняют побег.

  серии (серий нет); нет открытки от «новой семьи» — только текст; таймер от первого захода; потеря — 20 % монет и низкие

## Волна 34 J: остров и виджет на IslandEvents (26.10.2026)

- **Островок решает IslandEvents (§8).** `LiveActivityController.plan` берёт `IslandFeed.input` (снимок, прогноз,
  `Yard.fullAt`, поход из `Places`, побег) и кладёт в `ContentState` две карточки: `card` (сейчас) и `next` (после
  staleDate). Пушей нет, снаружи активность не обновить, поэтому вид «после» кладётся заранее, а вью выбирает его по
  `context.isStale` (`IslandLook.shown`). Всё хорошо или ночь хозяина — активность закрывается. Старое состояние без
  карточек рисуется прежним видом.
- **ContentState:** только новые необязательные поля `card`/`next` (`IslandCard`, Codable). Старые поля не тронуты.
- **Вид карточки — чистые данные** (`Shared/IslandLook.swift`, тесты в WSL): глиф, заголовок, таймер, начало
  полоски похода, кольцо, кнопка. Кнопки: голод → «Покормить», дома → «Погладить», последнее сердечко → то, что ядро
  примет в этот момент (`IslandPlan.pick`), остальное → «Открыть».
- **Пиксельный пёс:** 16×12, 6 поз (сидит, лежит, спит, ест, у миски, ушёл), 2–3 кадра по 0,5 с. Свинья копилки —
  тоже пиксельная: в SF Symbols свиньи нет.
- **Виджет — «экранчик»:** пластиковая рамка, небо по времени суток (утро/день/вечер/ночь, светлая и тёмная),
  полоса двора по ярусу, пиксельная сетка 6 %, виньетка. В тонированных режимах (accented/vibrant) декор не рисуем.
  Timeline — `WidgetLook.looks`: 24 кадра, сейчас и дальше по :00/:30 на 12 ч. Анимаций по секундам нет.
- **Прогулка ядра в виджете** — тоже полоска с пёсиком-точкой, подпись «Гуляет · вернётся в HH:MM».
- **«Собрать» из виджета:** `CollectIntent` (LiveActivityIntent, не в Shortcuts — лимит AppShortcuts) → `PetStore.mutate`
  под замком App Group → `WidgetLook.collect`: догнать ядро, `Yard.collect`, `DogLevel.settle` (4 XP за yard.collect
  по журналу, первый раз — ещё бонус «первый раз»).
- **Снимки:** `IslandLookSnapshotTests` — `ui-34-widget-*` (small/medium в светлой и тёмной, large, экран блокировки)
  и `ui-34-island-*` (развёрнутый, компакт, экран блокировки на каждое событие), время заморожено `petFrozenNow`.
- **Не проверено на телефоне:** система не крутит кадры в виджете и острове (виден первый кадр — пёс статичен);
  пёсик-точка на полоске похода стоит на месте между обновлениями (сама полоска идёт через
  `ProgressView(timerInterval:)`); реакции на кнопку в режиме карточек нет — сразу следующее событие.
